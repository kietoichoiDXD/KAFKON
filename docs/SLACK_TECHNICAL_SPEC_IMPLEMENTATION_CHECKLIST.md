## 2. Slack app credential fields

Never paste secret values into chat, source code, screenshots, or `.env.example`.

| Slack field | Local configuration status | Action |
|---|---|---|
| Date of App Creation | Not stored in this repository | Read it from the Slack app dashboard; it is metadata, not an OAuth setting. |
| App ID | Not configured; current OAuth routes do not need it | Copy from the Slack app's **Basic Information** page only if a future endpoint needs it. |
| Client ID | Configured in local `.env` | Keep server-side; do not expose in the browser or commit it. |
| Client Secret | Configured in local `.env` | Keep server-side and rotate if it has ever been shared publicly. |
| Signing Secret | Configured in local `.env` | Keep server-side. The current app does not yet expose Events API, slash-command, or interaction request handlers that consume it. |
| Verification Token | Not configured and not needed by the current code | Slack marks this as deprecated; use request signature verification with the Signing Secret when inbound Slack endpoints are added. |

Slack's request-signing documentation says Signing Secrets replace deprecated verification tokens and should be used to authenticate inbound requests: [Verifying requests from Slack](https://api.slack.com/authentication/verifying-requests-from-slack).

## 3. MVP work remaining from the specification

### OAuth, workspace isolation, and channel access

- [x] Validate OAuth `state` against the initiating browser session.
- [x] Allowlist cross-origin OAuth return URLs to the configured frontend origin.
- [x] Encrypt installation tokens at rest; never return them to the frontend.
- [x] Reject explicit `team_id` requests unless that browser session authorized the team.
- [ ] Add a visible workspace selector when a user has authorized more than one Slack team; switching should update the active team and refresh channel/thread state.
- [ ] Bind a Slack installation to a ScribeBA organization/user membership when multi-tenant accounts are introduced. The current session team list is not a substitute for membership/RBAC.
- [ ] Remove or explicitly disable the legacy global-token fallback after OAuth is verified in production; while it remains configured, do not let ambiguous links silently fall back to it.
- [ ] Add an install/reinstall flow that refreshes requested scopes and reports missing scopes and private-channel membership distinctly.

### Slack ingestion and conversational workflow

- [ ] Add signed inbound Events API, slash-command, and interactivity routes; validate HMAC signature and request timestamp before processing.
- [ ] Acknowledge Slack within the documented response window, enqueue work, deduplicate `event_id`, and retry safely.
- [ ] Add an encrypted, TTL-bounded message buffer; avoid relying on unrestricted history reads for distributed apps.
- [ ] Implement thread/session state, clarification answers, revisioning, and stale-action protection.
- [ ] Add Block Kit approve/request-changes actions; route all Slack and ClickUp writes through an idempotent outbox and require human approval before task creation.
- [ ] Implement channel↔room↔skill↔ClickUp-list linking and an expiring pairing code to prevent linking the wrong channel.
- [ ] Add message → claim → task provenance and two-way links, including edit/delete handling and retention rules.

### Data, reliability, and observability

- [ ] Replace single-host SQLite installation storage with a durable production store/secrets manager before horizontal scaling; design workspace ownership and tenant boundaries explicitly.
- [ ] If PostgreSQL/RLS is adopted, use transaction-local workspace context and test pool reuse across tenants; do not trust a client-supplied workspace header as authorization.
- [ ] Add rate-limit handling, backoff, cursors, and Slack API 429 telemetry.
- [ ] Add workspace-switch metrics and structured logs with no tokens, message bodies, or high-cardinality IDs as metric labels.
- [ ] Define retention and deletion behavior for buffered Slack content and uninstallation/revocation events.

## 4. Agent/skill work plan

Use these skills for the matching work; keep each agent's responsibility narrow and reviewable.

1. **Slack OAuth + workspace resolver** — `slack-bot-builder` and `api-security-best-practices`: OAuth state, `team_id` resolution, encrypted installation storage, session isolation, scopes, revocation, and fail-closed routing.
2. **Slack event ingestion** — `slack-bot-builder`: signature verification, Events API, commands/interactions, fast acknowledgements, event deduplication, queue/outbox, and retries.
3. **Conversation and evidence pipeline** — the repo's analyzer/grounding skills: thread reconstruction, deterministic evidence checks, clarification state, provenance, and safe ClickUp approval.
4. **Studio UX** — `react-best-practices` plus the local frontend design skill: explicit active workspace, understandable access errors, no silent legacy fallback, and accessible connection feedback.
5. **QA/security review** — `api-security-best-practices`: cross-workspace access tests, OAuth state replay, cookie/CORS behavior, secret scanning, private-channel access, and revocation.
6. **Optional Slack workspace actions** — `slack-automation` only when its required connected Slack MCP is available and the user explicitly wants a live Slack operation; do not use it as a substitute for implementing the product's backend OAuth.
